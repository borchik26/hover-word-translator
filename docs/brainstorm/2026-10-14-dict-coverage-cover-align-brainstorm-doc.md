# Покрытие словаря и выравнивание в режиме cover

## What We're Building

Два исправления по итогам использования на технических текстах.

1. **Покрытие словаря.** Сейчас не переводятся analyzer, deterministic, reused, shortcomings,
   blocs, monorepos, deployable, codebase, functionality, endpoints, interfaces. Причин две:
   - **Фильтр частотности.** `build_dict.py` берёт слово, только если оно есть в `en_50k.txt`
     (FrequencyWords, субтитры). Там нет endpoint, functionality, shortcoming. Формы
     (interfaces, reused, blocs, endpoints, shortcomings) тоже проходят через этот фильтр и
     отбрасываются, хотя лемма в словаре есть и kaikki знает связь через `form_of`.
   - **Нет русского перевода в Wiktionary.** У analyzer, codebase, deployable, deterministic,
     monorepo в kaikki нет ни одного `ru` в `translations`.
2. **Режим cover.** Сейчас плашка ставится от левого края слова (`left = rect.left`,
   `min-width = rect.width`), и длинный перевод уходит вправо, закрывая следующее слово. Нужно,
   чтобы правый край плашки совпадал с правым краем английского слова.

## Why This Approach

**Частотность: убрать фильтр для однословных статей.** Варианты были такие: расширить частотный
список (en_full или технический корпус) или снимать фильтр только с форм. Расширение списка
оставляет дыры на любом узком словаре. Если снять фильтр только с форм, endpoint, functionality
и shortcoming так и не появятся. Выбран вариант без фильтра для слов и форм: берём все
однословные статьи kaikki с ru-переводом и формы, у которых лемма есть в `w`. Для фраз (`p`)
фильтр остаётся: без него в словарь попадёт много мусорных сочетаний.

**Слова без перевода: морфологический фолбэк в рантайме.** Рассматривали ручной доп. словарь
(`extra.tsv` в git). Выбран фолбэк, потому что он покрывает весь класс слов, а не перечисленные
вручную. Срабатывает только при промахе словаря:
- **Суффиксы.** Отрезаем словообразовательный суффикс и ищем основу через тот же `resolve`
  (`w` + `f`): -er/-or (analyzer → analyze), -able/-ible (deployable → deploy), -ity,
  -ness, -ment, -ic/-istic и т. п., с правилами восстановления основы (`-e`, удвоенная
  согласная, `y`/`i`).
- **Составные.** Разбиваем слово на две словарные части (codebase → code + base, monorepo →
  mono + repo, если части есть в словаре) и показываем «код + база».
- **Метка.** Перед переводом ставится «≈», чтобы точный перевод отличался от догадки.
- **Выключатель.** Отдельный пункт меню Tampermonkey («Догадки: вкл/выкл»), хранится в
  `GM_setValue`, как режим оверлея и чёрный список сайтов.

Рассматривали варианты «только суффиксы» (codebase и monorepo остаются без перевода) и «без
метки» (нельзя отличить точный перевод от догадки).

**Cover: прижать к правому краю, лишнее растёт влево.** Рассматривали уменьшение шрифта
(плохо читается на коротких словах вроде «API») и перенос на несколько строк (закрывает
следующую строку). Выбран рост влево: плашка закрывает уже прочитанный текст слева, а не
следующее слово справа. Если плашка упирается в левый край viewport, её сдвигает вправо
(текущий `clampRect` это уже делает).

## Key Decisions

- **Частотный фильтр убираем для слов и форм, для фраз оставляем:** иначе специальная лексика
  не попадает в словарь.
- **Формы берутся, если лемма есть в `w`,** независимо от частотности самой формы.
- **Фолбэк только в рантайме (`core.js`), а не в сборке словаря:** словарь не раздувается,
  фолбэк можно выключить без пересборки.
- **Фолбэк срабатывает только при промахе** точного поиска (слово → форма → фраза).
- **Метка «≈»** у всех результатов фолбэка.
- **Выключатель фолбэка в меню Tampermonkey,** по умолчанию включён.
- **Cover выравнивается по правому краю слова;** если перевод шире слова, плашка растёт влево.
  Режимы blur и tooltip не меняются.

## Open Questions

- **Размер `dict.json` без фильтра.** Сейчас 20.6K слов, 10.9K форм. Нужно замерить рост и
  время `JSON.parse` (`scripts/bench-dict.mjs`). Если рост неприемлемый, ограничить по частям
  речи или отбросить статьи, где только редкие значения.
- **Точный список суффиксов и правил основы.** Например, deterministic → determinism?
  determine? Основы на -ism в словаре может не быть. Плюс ложные срабатывания: corner → corn
  (-er), city → c (-ity). Нужны минимальная длина основы и тесты на примерах.
- **Составные: минимальная длина частей** (≥3?), чтобы «a + bout» не давало мусор, и какой
  вариант разбиения брать, если их несколько (самая длинная левая часть?).
- **Формат составного перевода:** «≈ код + база» или «≈ код, база».
- **Cover + фраза, перенесённая на две строки:** сейчас перекрывается `rects[0]`; выравнивание
  по правому краю первой части фразы — проверить, что так ок.
- Скриншоты из запроса недоступны (CleanShot их уже удалил); поведение cover описано со слов.
